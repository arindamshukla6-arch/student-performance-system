# AI-Based Student Performance Prediction and Early Warning System

A B.Tech mini project prototype. Teachers and mentors enter four academic inputs for a student, and a machine learning model screens the student as **Low Risk**, **Moderate Risk** or **High Risk**, with suggested support actions.

> **Important:** this is a prototype. All data is **synthetic** (generated by `train_model.py`). Model scores describe that synthetic data only, not real-world accuracy. Predictions are screening indications and need human review. The project is **not ready for institutional use**.

## Features

- Login page (single demo account)
- Dashboard: totals, risk ribbon, attendance overview, academic overview, performance analytics, recent predictions
- Add Student: saves a record and predicts risk
- Predict Performance: quick what-if check, nothing saved
- Student Records: search, risk filter, sorting, details page, delete
- Analytics: risk pie chart, attendance vs performance, performance bands, model comparison
- Model Evaluation: accuracy, precision, recall, F1, confusion matrix, all calculated from the test set
- Risk Report (printable / save as PDF) and CSV export
- About page with limitations

## How the machine learning works

1. `train_model.py` generates 1,500 synthetic students and blanks about 3% of the values to practise missing-value handling.
2. The label comes from a documented rule: `score = 0.30*attendance + 0.30*internal% + 0.25*previous% + 0.15*assignment points`, plus random noise. At least 70 is Low, 58 to 70 is Moderate, below 58 is High.
3. A scikit-learn `Pipeline` fills missing values (median for numbers, most common for the category), standardises numbers and one-hot encodes assignment status.
4. The data is split 80/20 (stratified). Logistic Regression, Decision Tree and Random Forest are trained.
5. The model is **chosen using 5-fold cross-validated macro F1 on the training data only**. The test set is used just once, for the final report, so the chosen model is not tuned to it.
6. The selected pipeline is saved with Joblib and loaded by Flask. Confidence is the model's predicted probability (`predict_proba`).

Because the labels follow a nearly linear rule, Logistic Regression usually wins. That is a property of the synthetic data, not a general finding.

## Inputs and scales

- **Attendance:** 0 to 100%.
- **Internal marks:** marks obtained out of a configurable maximum (for example 20, 30 or 50), converted to a percentage.
- **Assignment status:** Completed, Partially Completed or Not Completed.
- **Previous performance:** percentage (0 to 100) or CGPA (0 to 10). CGPA is converted as CGPA x 10, which is only an approximation.

## Testing

```
python train_model.py

```

The tests cover input validation, model behaviour, login and CSRF protection, every page, add/search/sort/delete, CSV export and the missing-model case.

Manual check list: log in, add a student, open its details, run a quick prediction with invalid values (you should see clear errors), filter records by High Risk, download the CSV, open the Risk report and print it.

## Troubleshooting

- **Yellow banner "prediction model is not available":** run `python train_model.py`, then restart `python app.py`.
- **Reset demo data:** stop the app, delete `data/students.db`, start again.
- **Fonts look different offline:** fonts load from Google Fonts and fall back to system fonts. Charts work offline.
- **Port already in use:** change the port at the bottom of `app.py`.

## Limitations (please state these in your viva)

- Data is synthetic, so accuracy figures are not evidence of real-world performance.
- Only four inputs are used. Real academic risk depends on many other factors.
- One shared demo login: no roles, no password reset, no audit log.
- Real use would need student consent, privacy and data-protection review, proper authentication, and fairness and bias testing.
- A prediction is a screening aid. Decisions must be made by people who know the student.

## Viva notes

- **Why a Pipeline?** The same cleaning and encoding runs in training and in the web app, which prevents mismatches.
- **Why macro F1 to choose?** It treats the three risk levels equally, so a model cannot win by ignoring the smaller group.
- **Why cross-validation?** It lets us choose a model without touching the test set.
- **Why is accuracy not 100%?** Noise is added to the labels on purpose.
- **Why are names ignored by the model?** They carry no academic meaning and could introduce bias.
